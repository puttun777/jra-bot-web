## 0.1 ソースコードの Public 公開について（2026-10-26。D-180、UNRESOLVED E-7）
**区別**: ①本人 1 名・私的・非営利の**運用要件**（データの扱い）と、②**ソースコードを Public リポジトリで公開すること**は別の論点。①が満たされていても、②が規約上許されるとは限らない。②について JRA-VAN から**公開許可は得ていない**（回答なし。許可を得たものとは扱わない）。
- Git に含めないもの（公開前提）: 実データ（JV-Data・DB ダンプ）、JV-Link SDK・DLL・PDF 仕様書、学習済み実モデル、利用キー・秘密。`.gitignore`・`repo-hygiene`・履歴スキャン（gitleaks。全履歴で実秘密 0 件）で確認。テスト・フィクスチャは合成データのみ（`data_classification: synthetic`）。
- 仕様書由来の可能性がある記載: `JVLINK_DESIGN` §1.4 のバイト位置表は、参照元 `jra-bot`（MIT・Public）の実装由来で、公式の JV-Data 仕様書の内容と重なる可能性がある。**Public 化に備えて位置・桁数を削除**し項目名だけにした（現在のツリー。**Git 履歴には残る**。履歴は書き換えない方針。履歴に残る分は、参照元が Public で同じ値を公開している範囲、という整理で、権利上の問題がないとは断定しない）。
- `agent/` の JV-Link COM 呼出し（`JVInit/JVOpen/JVRTOpen/JVRead/JVClose`、ProgID `JVDTLab.JVLink`）は参照元実装が使う呼出し名と戻り値の解釈（二次情報）。JV-Link の内部解析・プロトコル解析は含まない。仕様書の確認が 0 件のため `SpecRegistry` のゲートで実取得は始まらない。
- 規約第9条（JV-Link の解析禁止等）に当たる記載・コードはないと**読める**が、条文全文は未読のため断定しない。
- 判断: 公式回答（E-7）が得られるまで、**実データのクラウド投入ゲートは従来どおり維持**し、ソースの Public 化は**ユーザーの判断**（リスクを承知した上での操作）とする。リスクを下げたい場合は、Public 化せず Private のまま CI 分数を節約する運用（`classify.py`）を続ける。
- 表の #11 は「低リスク（未確認）」のまま。回答があれば更新する。

## 5. 実装・運用上の制約（規約由来）
1. **実データを Git（Private 含む）・CI のログ・Issue・PR に含めない**。ゴールデンテストは仕様書のレイアウトから生成した合成レコードで行う。実データでの突合は利用者のローカル環境のみ。
2. ログにレコード本文を書かない（サイズ・規約）。
3. **Discord 等の通知先は本人専用**。共有チャンネルへは送らない（#6）。
4. ダッシュボードは認証必須・テナント境界必須。ブラウザ向け API でも他テナントのデータを返さない。
5. 外部サービス（生成 AI 等）へ JRA-VAN データを送らない（#16）。
6. 学習済みモデル・データセットは Git に含めない（現行のまま）。
7. DB バックアップ・エクスポートも同じ扱い（保存先は同一クラウド・日本リージョン、公開しない）。
8. **一般公開は JRADB 取得を条件**とし、それまでは行わない（#8）。ただし技術的拡張性（利用者増に耐える設計）は維持する。

## 7. 段階的な運用方針（案）
1. **Phase 0（今）**: 設計・実装・テストは**合成データのみ**で進める（規約上の懸念なし）。
2. **Phase 1（Q1/Q2 の回答前）**: 本番データ投入は保留可。許容できる範囲は「契約者本人が自分の PC のみで取得・保存」まで（従来運用）。クラウドへ実データを置くのは回答後。
3. **Phase 2（Q1〜Q3 の回答後）**: 回答に従い、案 A で 2 テナント運用を開始。
4. **Phase 3（一般公開の検討時）**: JRADB を前提に別途設計（本書の範囲外）。
→ **この方針により「クラウド保存は未確認だから実装しない」ではなく「実装は進めつつ実データ投入の可否だけを管理する」ことができる**。ユーザー判断が必要（§8）。
